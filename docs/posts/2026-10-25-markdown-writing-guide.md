## Markdown 是什么

Markdown 是用普通文本表达标题、段落、链接等结构的写作方式。源文件本身可读，适合备份和版本管理；网站再把这些结构转换成 HTML。

槐序霁先由 `docs/.vitepress/theme/posts.js` 扫描 `docs/posts/*.md`，使用 gray-matter 分离 YAML 元数据与正文；详情页把正文交给 `components/MarkDown.vue` 中的 markdown-it。VitePress 负责站点构建与文章路径，但正文能力以这个独立渲染器为准。

## 从一个文件开始

使用 `YYYY-MM-DD-slug.md` 命名，放在 `docs/posts/` 第一层。例如：

```text
docs/posts/2026-10-25-my-first-note.md
→ /post/my-first-note.html
```

日期前缀会被路由扫描器去掉。Slug 使用唯一的小写英文和短横线，避免空格、斜杠和重名；不要把草稿放在这里。当前没有 `draft` 或未来日期过滤，目录里的文章都会进入构建。

## Frontmatter：文章信息放在哪里

文件第一行开始写 YAML，两端使用独占一行的 `---`：

```yaml
---
title: "我的第一篇写作记录"
date: "2026-10-25"
category: "使用教程"
tags: ["Markdown", "笔记"]
cover: "https://t.alcy.cc/ysz"
coverTitle: "写作手记"
description: "记录创建本地文章、检查 Markdown 效果和构建发布的完整过程。"
hot: 1
---
```

渲染结果：这些字段生成标题、日期、分类、标签、封面和摘要，不会把 YAML 原文显示在正文里。适用于每篇正式文章。

| 字段 | 实际用途与建议 |
| --- | --- |
| `title` | 列表、详情 H1、HTML title 与 OG 标题共用；含冒号或井号时加引号 |
| `date` | 显示与排序使用的发布日期，建议带引号的 `YYYY-MM-DD` |
| `category` | 一个分类字符串；新分类自动聚合，不写成数组或 `categories` |
| `tags` | 字符串数组；同一个标签保持相同大小写与用词 |
| `cover` | 封面地址；不填回退主题默认图，当前默认为第三方随机图片接口 |
| `coverTitle` | 标题区域的独立小副标，不填留空 |
| `description` | 列表摘要、meta description 和 OG 描述，正式文章显式填写 |
| `hot` | 静态展示数字，通常为 1，不是实际阅读量，0 会回退为 1 |

目前没有 `updated`、`seoTitle`、`seoDescription`、`published` 等文章功能。需要记录更新时间，可在正文写“最近更新：日期”，保留原发布日期。

## 分类、标签与 SEO 描述

分类用于文章的主要用途，例如“项目文档”“使用教程”“部署教程”。标签用于交叉检索，一般选择少量主题词；不要用 `Vue`、`vue`、`Vue.js` 表达同一个标签，当前筛选按原字符串精确匹配。

摘要写一到两句纯文本，说明“讲什么、读者能完成什么”，避免堆关键词。例如本教程的描述同时提到当前渲染实现、操作内容与模板，而不重复列一串搜索词。

`title` 自动用于 `文章标题 | 槐序霁`，不需要再加一个 SEO 标题。省略 `description` 时，程序取正文第一条非空且不以 `<` 开头的行；如果第一行是 `## 背景`，摘要可能就只剩章节名称。

SSR 会输出独立标题、描述与 OG `article` 信息。随机封面不作为稳定 `og:image`：改用主题 `defaultShareImage` 指向的本地图片；正式域名未确定时省略其绝对 URL。正式 `url` 填入 `docs/.vitepress/site.js` 后重新构建，才生成 canonical、og:url、sitemap 和 robots 的 Sitemap 地址。

## 标题：一级、二级、三级

```markdown
# 独立文档的一级标题
## 文章章节
### 章节中的步骤
```

效果：分别产生 H1、H2、H3；主题为二级及以下标题添加装饰图标。适用场景：独立 Markdown 文档可用 `#`，博客文章已有 Frontmatter 生成的 H1，因此正文从 `##` 起，再用 `###` 分组，不重复文章标题。

当前正文没有自动目录或标题 ID 插件，不应假设某个 `#中文标题` 链接一定能跳到对应标题。

## 普通段落与换行

```markdown
第一段记录背景。
同一段中的普通换行通常仍属于这一个段落。

空一行后开始第二段。
```

效果：空行分隔段落；普通单次换行不会自动产生新的段落。适用于叙述过程和解释原因。

如果确实需要段内换行，可以在前一行末尾保留两个空格，或使用当前允许的 `<br>`。两空格很容易被编辑器清理，通常直接分段更清楚。

## 加粗、斜体和删除线

```markdown
**重要结论**、*适度强调*、~~已经失效的说法~~。
```

效果：**重要结论**、*适度强调*、~~已经失效的说法~~。适用场景：突出结论、轻度强调和标记失效信息；不必把整段加粗。

## 无序与有序列表

```markdown
- 准备文章
- 检查摘要

1. 启动开发预览
2. 执行生产构建
```

效果：前两项显示为项目列表，后两项显示为编号步骤。无序列表适合并列事项，有序列表适合有先后关系的操作。列表前后留空行，避免和上一段粘在一起。

## 链接

```markdown
[项目介绍](/post/about-huaixuji.html)
[Markdown-it 官方项目](https://github.com/markdown-it/markdown-it)
<https://vitepress.dev/>
```

效果：显式 Markdown 链接及尖括号包裹的完整网址会变成可点击链接。适用于站内文章互链和资料来源。

当前 `linkify: false`，单独写一段裸网址不保证自动变成链接。不要链接到 `/posts/日期-slug.md`，那里是被排除的文章源文件目录；也不要使用本机 `E:\...` 路径作为网页链接。

## 图片与替代文字

```markdown
![槐序霁站点图标](/assets/apple-touch-icon.png?vw=180&vh=180 "本地图片示例")
```

效果如下：

![槐序霁站点图标](/assets/apple-touch-icon.png?vw=180&vh=180 "本地图片示例")

适用场景：截图、步骤说明和配图。此例复用已有本地图标，不需要下载素材。正式文章可将有权使用的图片放到 `docs/public/images/posts/<slug>/`，网页路径从 `/images/posts/` 开始。

方括号是图片内容说明，用于 alt 文本；圆括号末尾的引号内容是可选图片说明。主题会把 title，或没有 title 时的 alt，显示在图片下方。优先使用普通说明文字，避免在这里混入 HTML。

正文图片已有懒加载；成对提供真实的 `vw`、`vh` 像素尺寸，会输出宽高属性，帮助加载前保持比例。它们不会压缩原图，不能用很小的显示尺寸掩盖很大的下载文件。只有封面使用固定 16:9 裁切，正文图片仍按自身比例显示。

## 引用

```markdown
> 先把标准流程做好，再处理可选优化。
```

效果：显示为独立引用块。适用于引用资料、提醒条件或说明背景；外部引文应同时注明出处。

## 表格

```markdown
| 阶段 | 检查内容 |
| --- | --- |
| 预览 | 正文、图片与链接 |
| 构建 | 静态 HTML 与资源 |
```

效果：两列表格；主题将表格放在可横向滚动的容器中。适用于字段解释、参数对照和简短比较，手机上避免放入过多长段落。

| 阶段 | 检查内容 |
| --- | --- |
| 预览 | 正文、图片与链接 |
| 构建 | 静态 HTML 与资源 |

## 行内代码与代码块

````markdown
运行 `npm run docs:build`。

```js
const title = '槐序霁'
console.log(title)
```
````

效果：命令成为行内代码，程序成为保留缩进和换行的代码块。适用于命令、路径、变量和多行示例。语言名会生成对应 class，但当前渲染器没有逐词高亮、复制按钮或行号，不要把这些当作已接入功能。

展示 Markdown 源码时，外层使用四个反引号，内层示例使用三个；如果示例本身含四个，外层继续加长。关闭围栏必须与外层匹配，否则后续章节会被吞进代码块。

## 分割线

```markdown
上一部分结束。

---

下一部分开始。
```

效果：正文中显示水平分割线。适用于明确结束一个主题。它前后留空行，并且位于 Frontmatter 结束之后；文件开头的成对 `---` 是 YAML 边界，作用不同。

## 任务列表：当前只是文本

```markdown
- [ ] 检查手机效果
- [x] 填写文章摘要
```

效果：当前 markdown-it 没有任务列表插件，显示为带 `[ ]`、`[x]` 字样的普通列表，不产生可交互复选框。适用于纯文本待办记录；不要把勾选动作当作站点会保存的状态。

## 其他实际支持的写法与限制

反斜杠可以转义 Markdown 符号：

```markdown
\*这里显示星号，不是斜体\*
```

效果：显示字面星号。适用于需要解释符号本身的教程。

当前启用了原始 HTML，可使用浏览器原生的折叠说明：

```html
<details>
<summary>查看补充说明</summary>
<p>这里放不影响主流程的补充内容。</p>
</details>
```

效果：浏览器显示可展开的说明区。适用于附加信息。这里只写自己审阅过的 HTML，不粘贴来源不明的脚本；它不是 Vue 组件系统。

数学公式、脚注、任务复选框插件、VitePress `::: tip` 容器以及正文 Vue 组件未启用。`$x^2$` 不会排版成数学公式；需要表达时用文字或代码即可。当前没有理由为一篇文章更换整个渲染系统。

## 从预览到发布

1. 复制 `docs/文章模板.md` 到文章目录，先检查 slug 唯一。
2. 填写 Frontmatter、正文和真实图片路径；保存文件。
3. 在 `blog` 根目录首次执行 `npm ci`，然后运行 `npm run docs:dev`，打开终端给出的地址。
4. 检查文章直链、分类、标签、摘要、代码与图片；至少看一次桌面和手机。新路径没有出现时重启开发服务。
5. 执行 `npm run docs:build`，再运行 `npm run docs:preview` 检查生产结果。
6. 将完整 `docs/.vitepress/dist/` 交给静态部署流程；有 Git 仓库时按项目规则提交，不擅自 push。部署细节见 [部署指南](/post/huaixuji-deployment-guide.html)。

## 修改已发布的文章

| 修改内容 | 当前结果 |
| --- | --- |
| 改正文、摘要、标题 | 重新构建后更新内容；slug 不变则 URL 不变 |
| 改 Frontmatter 的 `date` | 更新显示日期与排序，URL 不变 |
| 只改文件名日期前缀，仍满足格式 | 前缀仍被剥离，slug 未变则 URL 不变；排序仍由 `date` 决定 |
| 改文件名中的 slug | URL 改变；当前没有自动重定向，需要同步站内链接与部署旧地址处理 |

修订时通常保留发布日期，在正文注明更新日期。没有更新时间展示字段，不要为了改正文重复发布一篇相同内容。

## 常见错误

| 现象 | 先检查什么 |
| --- | --- |
| 构建提示 YAML 解析失败 | 冒号、缩进、引号，头部 `---` 是否配对 |
| 标签页面出错 | `tags` 必须是数组，不能写成逗号分隔的单个字符串 |
| 摘要只剩章节名 | 显式填写纯文本 `description` |
| 新文章直链不存在 | 文件是否在第一层、名称是否符合规则、是否重启开发并重新构建 |
| 后续内容都变成代码 | 检查围栏长度与闭合位置 |
| 图片 404 或跳动 | 文件路径、真实文件存在与否，成对 `vw` / `vh` 是否正确 |
| 某个扩展语法没有效果 | 核对本教程的实际支持清单，而非默认 VitePress 主题的能力 |
| 发布后还是旧内容 | 确认上传了新产物，检查 HTML 与 CDN 缓存，避免新旧目录混合 |

---
